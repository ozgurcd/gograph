# Scrinium Guide

## Purpose and authority

Scrinium is the governed write interface for durable project memory. Use it for decisions, rationale, security constraints, provenance, and cross-session handoffs. Current source, tests, generated contracts, release artifacts, and live services remain authoritative for behavior. Generated gograph wiki pages are freshness-sensitive caches.

## Conditional use

Do not start Scrinium or preload wiki pages for read-only questions, status checks, trivial edits, or ordinary work that creates no durable cross-session knowledge. A project change alone does not require a Scrinium session.

Use Scrinium when maintained wiki content must change or when a material architecture, security, release, governance, or externally sourced decision should persist.

## Governed workflow

1. Start one server from the repository root with `scrinium ./scrinium.json`.
2. Call `capabilities` once for that server connection, then call `begin_session`.
3. Read `index.md` and `agent-rules.md`, which the server requires before writes. Read only additional pages directly relevant to the task.
4. Write only durable knowledge through Scrinium. Do not log formatting cleanup, routine implementation details, or facts already evident from source control.
5. Call `session_status`, satisfy required log/index/source-registry maintenance, and call `finish_session`.

Do not call session lifecycle tools when no Scrinium session was started.

## Generated context

Ignored pages generated by `gograph wiki` are not durable Scrinium records. Check `gograph stale` before trusting them and rebuild only when structural context is needed.

## Governance

Protected pages cannot be updated or appended through Scrinium. Propose their changes with `create_draft`. Scrinium governs only writes made through its tools; it is not a security boundary for arbitrary filesystem edits.

## Scrinium 0.1.3 limitations

The current `enforce-agents` template emits an unconditional workflow and an absolute local path, so this repository maintains a conditional, repository-relative policy instead. The current linter also classifies `sources/README.md` as a source record and reports missing metadata; treat that as a known false positive until the implementation can exclude directory guides.
